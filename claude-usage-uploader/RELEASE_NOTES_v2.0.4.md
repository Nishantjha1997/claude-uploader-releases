# Claude Usage Uploader v2.0.4

Fleet reliability and self-update recovery release.

## Uploader

- Uses a versioned, side-by-side executable during updates so Windows never has
  to overwrite the currently running process.
- Reports `UPDATED` only after the new process has restarted, loaded its saved
  configuration, repaired background-task registration, and contacted the
  dashboard.
- Runs as one hidden Task Scheduler worker with restart-on-failure, plus an
  independent health task that restarts a worker whose local heartbeat stalls.
- Removes the legacy visible `ping 127.0.0.1` launcher loop.
- Uses an atomic process lock to prevent duplicate uploads.
- Supports dashboard-controlled daily, weekly, and monthly schedules, including
  local time, weekday, and month day in the configured time zone.
- Bundles a pinned native ccusage tool; production installations no longer rely
  on Node.js or npm being installed or healthy on each user's computer.
- Keeps failed dashboard notifications in a durable replay queue.
- Selects the correct macOS update for Intel or Apple Silicon.
- Staggers scheduled uploads with a deterministic per-machine jitter (0-15 min)
  so the whole fleet never hits Drive/Apps Script at the same instant.
- Never begins a self-update while an upload or retry is in flight.
- macOS/Linux background entries now pass `--scheduled`, so task registration
  is no longer rewritten on every respawn.

## Dashboard and Apps Script

- Repairs malformed RegisteredDevelopers headers and invalid roster values.
- Accepts both the deployed Script Property HMAC secret and the compiled fleet
  secret during migration while retaining timestamp and replay protection.
- Returns the complete upload schedule to every client.
- Stops deleting unknown spreadsheet tabs; only known obsolete tabs are removed.

## Recovery package

Windows users stuck on an older release can run `Repair-Claude-Uploader.cmd`
from a folder containing the v2.0.4 Windows binary and their externally supplied
`service-account-key.json`. The repair preserves configuration, removes only this
utility's old tasks/processes, installs the versioned binary, and recreates the
supervised background tasks.

## Release order

1. Back up and deploy Apps Script.
2. Build and verify all platform artifacts and checksums.
3. Install the repair package on a small Windows canary group.
4. Publish release assets.
5. Update the Gist manifest last so fleet rollout begins only after verification.

Checksums are generated by CI and must be copied here only after the release
artifacts have passed smoke tests.
